## Overview

sk59 builds, deploys, and manages a **multi-provider AI gateway** — an OpenAI-compatible reverse proxy that pools accounts across Cloudflare Workers AI, OpenRouter, and any compatible LLM provider. Unlike cf-proxy (single-provider CF Workers), this is a **sovereign multi-provider mesh** that:

1. **Pools ALL free-tier AI providers** — not just Cloudflare. Knows every free LLM endpoint.
2. **Account rotation + neuron/budget tracking** per provider with proactive skip
3. **Intelligent model routing** — picks best provider for each model based on cost/speed/availability
4. **Built-in fallback chain** — if CF hits 429, auto-routes to next provider
5. **React dashboard** — pool health, neuron usage, cost tracking, request logs
6. **Zero-cost operation** — designed to run on free tiers only, maximizing $0 spend
7. **Drop-in OpenAI SDK compatible** — any code using OpenAI SDK works by changing base_url
8. **Integrated with SUPERAGENT V7** — feeds into sk7 (Inference Systems) provider cascade

### Why This Matters

```
Problem:  Free AI APIs have per-account rate limits (CF: 10k neurons/day, 
          OpenRouter: variable, Groq: RPM limits). One account = limited throughput.
          
Solution: Pool N accounts per provider, rotate automatically, track budgets.
          Multi-provider means even if Cloudflare is down, traffic auto-routes.
          
Result:   Virtually unlimited free AI inference for bots, agents, and apps.
          Zero API costs. Full OpenAI SDK compatibility.
```

**.env structure:**
```env

GATEWAY_HOST=0.0.0.0

# Cloudflare Workers AI (can have multiple accounts)
CF_ACCOUNTS='[{"token":"cfut_xxx1","id":"acct1"},{"token":"cfut_xxx2","id":"acct2"}]'

# Groq

# Provider config
```

### Phase 2: Account Pool Management

The gateway manages account pools per provider:

```
Cloudflare Account Pool:
┌──────────┬─────────┬──────────┬──────────────┐
│ Account  │ Status  │ Neurons  │ Requests     │
├──────────┼─────────┼──────────┼──────────────┤
│ acct-1   │ active  │ 7,234    │ 1,245        │
│ acct-2   │ cooldown│ 10,000   │ 2,100        │
│ acct-3   │ active  │ 2,156    │ 432          │
│ acct-4   │ active  │ 5,891    │ 987          │
└──────────┴─────────┴──────────┴──────────────┘
```

**Auto-rotation logic:**
1. Pick account with lowest neuron usage (or round-robin if all equal)
2. If account returns 429 → cooldown for `CF_COOLDOWN_429` seconds
3. If account hits 10,000 neurons → skip until 00:00 UTC
4. If all CF accounts exhausted → fallback to next provider
5. Reservation system: deduct estimated neurons BEFORE request, refund on failure

### Phase 3: Intelligent Model Routing

Instead of hardcoding models, the gateway:
1. Fetches live model lists from ALL providers
2. Builds a unified model catalog
3. Routes requests to the best provider for each model

**Routing priority:**
```
Model: llama-3.3-70b-instruct
├── 1st try: Cloudflare Workers AI (free, fast, 0 cost)
├── 2nd try: Groq (free tier, fast, RPM limit)
├── 3rd try: OpenRouter (free models, variable speed)
├── 4th try: Together AI ($1 credit)
└── Fallback: Return 503 if all providers exhausted
```

**Model resolution (like cf-proxy but multi-provider):**
```
Input: "llama-3.2-1b-instruct"
├── CF: @cf/meta/llama-3.2-1b-instruct
├── OpenRouter: meta-llama/llama-3.2-1b-instruct
├── Groq: llama-3.2-1b-instruct
└── Together: meta-llama/Llama-3.2-1B-Instruct
```

### Phase 4: Neuron Budget Tracking

Cloudflare uses "neurons" as currency (1 neuron ≈ 1 inference unit). The gateway estimates:

```javascript
neurons = prompt_tokens × RATE_IN + completion_tokens × RATE_OUT

// Rates from CF pricing page (lib/neurons.js)
const RATES = {
  "@cf/meta/llama-3.3-70b":  { in: 0.10, out: 0.25 },
  "@cf/deepseek-ai/deepseek": { in: 0.05, out: 0.10 },
  "@cf/microsoft/phi-4":      { in: 0.02, out: 0.05 },
  // ... all models
};
```

**Proactive skip:** If estimated neurons > remaining, skip account BEFORE request.

### Phase 7: SUPERAGENT V7 Integration

The gateway integrates with sk7 (Inference Systems):

```python
# tools/model_registry.py — add gateway as provider
from model_registry import ModelRegistry

reg = ModelRegistry()
reg.add_provider("gateway", {
    "base_url": "http://localhost:8750/v1",
    "api_key": "sk-your-auth-key",
    "models": "auto",  # Fetched from /v1/models
    "priority": 0,     # Highest priority (free tier)
    "cost_per_1k": 0,  # Free
})

# Now all LLM calls cascade through gateway first
response = reg.call_with_cascade(messages)
# Tries: gateway → anthropic → openrouter → deepseek → groq
```

## Safety Rails

1. **No key exposure** — API keys never logged, dashboard shows masked keys
2. **Rate limit protection** — Gateway-level rate limiting prevents abuse
3. **Account isolation** — One account hitting 429 doesn't affect others
4. **Fallback guarantee** — At least 2 providers configured or refuse to start
5. **Usage alerts** — Notify if pool drops below 20% capacity
6. **Auto-suspend** — If all providers exhausted, return clear error (not silent failure)
7. **Request logging** — All requests logged (in-memory ring buffer, 500 entries)
8. **Neuron estimation** — Conservative estimates (over-estimate to avoid overrun)

## Quick Start for SUPERAGENT V7

```bash
# Deploy from SUPERAGENT
# sk59 auto-handles: clone, configure, deploy, integrate

# 1. Deploy gateway
python3 tools/gateway_manager.py deploy \
  --providers cf,openrouter,groq \
  --cf-accounts cf_accounts.json \
  --port 8750

# 2. Add to model registry
python3 tools/model_registry.py add-provider gateway \
  --base-url http://localhost:8750/v1 \
  --api-key sk-your-key \
  --priority 0

# 3. Verify
curl http://localhost:8750/health
# {"providers":{"cf":{"total":3,"available":3},"openrouter":{"available":true},"groq":{"available":true}}}

# 4. Use in any code
# Just change base_url — everything else is identical to OpenAI
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8750/v1", api_key="sk-your-key")
response = client.chat.completions.create(
    model="llama-3.3-70b-instruct",
    messages=[{"role":"user","content":"Hello!"}]
)
```

## Troubleshooting

| Issue | Cause | Fix |
|-------|-------|-----|
| All accounts 429 | Rate limit spike | Increase cooldown, add more accounts |
| Model not found | Model not available on any provider | Check `/v1/models` for available models |
| Gateway crashes | Memory leak | Check logs, increase VPS RAM, add swap |
| High latency | Faraway CF datacenter | Use provider closer to VPS region |
| Auth failures | Wrong API key | Check `.env` or `GATEWAY_API_KEY` |
| Zero accounts | Import failed | Check import source, verify tokens valid |
