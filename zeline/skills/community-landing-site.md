# Community Landing Site

> Build multi-page static community landing sites with auto-updating content feeds (RSS/news, prices, airdrops). Dark theme, card-based layout, responsive. Pure HTML/CSS/JS — no framework. Deploy to GitHub Pages or Cloudflare Pages.

## When to Use

User asks to build a community website / landing page — especially:
- Web3 / crypto / airdrop community sites
- Auto-updating news from RSS feeds
- Live price dashboards
- Multi-page: home, content, community pages
- "Kayak airdropfinder.com" style sites
- Any static site where content refreshes from external sources

## Site Structure

```
project-site/
├── index.html            — Landing page (hero, stats, featured content)
├── airdrops.html         — Airdrop/testnet listing (reads data.json)
├── news.html             — Auto-updating news feed (reads data.json)
├── research.html         — Market analysis + live prices
├── community.html        — Telegram group cards
├── assets/
│   └── style.css          — Dark theme styling
├── data.json             — Structured content (generated by updater script)
└── update-news.py        — Cron script to refresh data.json from RSS
```

## Architecture

```
User visits site
    │
    ▼
Static HTML pages (JS fetch `data.json?_={timestamp}`)
    │
    ▼
data.json — generated by update script, refreshed by cron
    │
    ▼
update-news.py — fetches RSS feeds, writes to data.json
    │
    ▼
Cron job — runs script every N hours (typically 6h)
```

## Clean / Professional Mode

When the user asks for "profesional," "simpel," "clean," "minimal," or "elegant" — strip the heavy animations and use a restrained palette. This is NOT a different site; it's the same structure with lighter styling. The user is telling you they want substance over spectacle.

**What to remove (vs animation-heavy default):**
- Drop `<div class="particles">` and all blob divs entirely — no fixed animated background layers.
- Drop the `.card::before` conic-gradient glow — too distracting.
- Drop `.stat-num` count pulse animation — keep static numbers.
- Drop `.logo-text` animated gradient text — logo image alone is cleaner.
- Drop the `animation: logoSpin` on the logo SVG — no wobble.

**What to keep (essential):**
- Hero staggered slide-up animation — clean entrance, keep it.
- `.fade-in` keyframes for JS-rendered cards — keep.
- `.card:hover` subtle lift + shadow — professional micro-interaction, keep.

**Clean CSS palette (darker, deeper, less neon):**
```css
:root {
  --bg: #08080f;           /* deeper navy base */
  --bg2: #10101a;
  --bg3: #161625;
  --surface: #1a1a2e;     /* card surface distinct from bg */
  --text: #e8e8f4;
  --text2: #8a8aaa;
  --text3: #5a5a7a;       /* third tier for meta/captions */
  --accent: #7c3aed;
  --accent2: #8b5cf6;
  --accent3: #a78bfa;     /* lighter violet for highlights */
  --rose: #f43f5e;        /* replaces red for status */
  --green: #10b981;
  --gold: #f59e0b;
  --border: rgba(139,92,246,0.15);
  --border2: rgba(255,255,255,0.06);  /* subtle card border */

```

**Clean navbar:** 56px height (not 64px), `background: rgba(8,8,15,0.85)`, `backdrop-filter: blur(20px) saturate(180%)` — true glassmorphism. Logo image only (28px height), no text alongside.

**Clean hero:** `min-height: 70vh` (not 80vh), subtle radial-gradient overlay on `::before` pseudo-element instead of animated blobs — no moving background elements.

**Clean typography:** Add Inter font via Google Fonts CDN (`wght@400;500;600;700;800`). `letter-spacing: -0.03em` on headings. `-webkit-font-smoothing: antialiased` on body.

**Clean cards:** `var(--surface)` background (not var(--bg2)), `var(--border2)` border, subtle `var(--shadow)` on hover (no glow, no transform beyond -1px Y).

**Clean section headers:** Flex row with `<h2>` left + "View all →" link right, replacing inline emoji headings. `padding: 72px 0` section spacing.

Two logo modes:

**SVG inline** — use when no image logo available. SVG draws a star-like icon with gradient fills. Add `animation: logospin 10s linear infinite` (gentle wobble) on the SVG element:
```css
@keyframes logoSpin { 0% { transform: rotate(0deg); } 25% { transform: rotate(5deg); } 75% { transform: rotate(-5deg); } 100% { transform: rotate(0deg); } }
```

**Image logo** — user sends PNG/JPG via Telegram chat. The image lands in `~/.zeline/cache/images/`. Copy to `assets/logo.png` and reference as `<img src="assets/logo.png" style="height:36px;width:auto;">`. Keep the `span.logo-text` alongside.

**Logo with baked-in background → make transparent.** Logos sent as screenshots or exported PNGs very often have a solid opaque background (black or white) baked into the alpha channel — i.e. RGBA mode but corners are `(0,0,0,255)` not `(0,0,0,0)`. On a dark site this shows an ugly black box behind the logo. Detect by sampling corner pixels; if they're opaque and near-uniform, strip the background:

```python
from PIL import Image
from collections import deque
im = Image.open('assets/logo.png').convert('RGBA')
w, h = im.size; px = im.load()
def near_bg(p, tol=45):  # tune tol to the bg color range
    return p[0] <= tol and p[1] <= tol and p[2] <= tol
visited = bytearray(w*h); q = deque()
# seed from all 4 edges only — keeps interior dark strokes intact
for x in range(w):
    for y in (0, h-1):
        if near_bg(px[x,y]): q.append((x,y)); visited[y*w+x]=1
for y in range(h):
    for x in (0, w-1):
        if near_bg(px[x,y]) and not visited[y*w+x]: q.append((x,y)); visited[y*w+x]=1
while q:
    x,y = q.popleft(); px[x,y] = (0,0,0,0)
    for nx,ny in ((x+1,y),(x-1,y),(x,y+1),(x,y-1)):
        if 0<=nx<w and 0<=ny<h and not visited[ny*w+nx] and near_bg(px[nx,ny]):
            visited[ny*w+nx]=1; q.append((nx,ny))
im = im.crop(im.getbbox())          # trim transparent border
im.thumbnail((512,512), Image.LANCZOS)
im.save('assets/logo-transparent.png')
fav = im.copy(); fav.thumbnail((64,64), Image.LANCZOS); fav.save('assets/favicon.png')
```

Key points: flood-fill **from edges only** so interior dark shapes survive; `tol` must match the background color (raise for near-white `255` backgrounds via a separate predicate); always crop to bbox and regenerate a small favicon from the same transparent source. Then reference `assets/logo-transparent.png` in the navbar and `assets/favicon.png` as `<link rel="icon">`.

## Auto-Content Pattern (update-news.py)

Script structure:
1. Fetch RSS from Google News (language-specific queries)
2. Parse items: title, link, description, date
3. Deduplicate by title prefix
4. Write to data.json with `last_update` timestamp
5. Tag items (kripto, airdrop, etc.)

```python
# Key pattern:
sources = [
    ("RSS_URL", "tag_name"),
    # Multiple sources per site
]
# Dedup by title[:60]
# Limit to N items (e.g., 10)
```

**JSON format**:
```json
{
  "news": [{"title":"...", "link":"...", "desc":"...", "tag":"kripto", "date":"..."}],
  "airdrops": [{"name":"...", "chain":"...", "status":"live", "link":"..."}],
  "last_update": "DD/MM/YY HH:MM WIB"
}
```

**Cache busting**: Append `?_={Date.now()}` to fetch URL.

## Pitfalls

- **Logo with baked-in background.** User-uploaded PNGs often have a solid opaque background (black or white) even in RGBA mode — corners will be `(0,0,0,255)`. On a dark site this looks like a black box around the logo. Always sample corner pixels first; if they're opaque and near-uniform, run the PIL flood-fill transparency script before using the logo.
- News RSS from Google News may return stale/old articles. Acceptable for auto-feed.
- CoinGecko API rate-limited but fine for one fetch per page load.
- Yahoo Finance blocks requests without User-Agent header — ALWAYS set it.
- JSON fetch from local file needs `?_={timestamp}` cache buster or browser caches old data.
- Mobile navbar hamburger: use inline onclick, no JS dependencies.
- When pages use minified HTML (single-line navbar), `patch` tool fails to match old_string. Use `write_file` for full rewrite instead of `patch` on those pages.
- Cron scripts CRITICAL: path must be relative filename in ~/.zeline/scripts/, not absolute.
- When the user says "profesional" / "simpel" / "clean" about styling, DO NOT build the particles+blobs+card-glow version first. That's the wrong starting point — start with Clean Mode and only add animations if asked.
